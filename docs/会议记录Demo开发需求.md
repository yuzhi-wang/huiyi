# Android 会议记录 Demo 开发需求

> 历史需求，保留用于追溯。2026-09-13 已按用户最终计划一次实现全部功能；冲突时以项目 README 和《使用与打包.md》为准。模型配置不是录音/回放的前提，不设置两次交付关卡。

更新日期：2026-09-11

本文用于在新仓库、新对话中启动开发。目标是考核用的功能性 Demo，以跑通完整流程为优先，不按正式商业产品扩展架构。

## 1. 项目目标

开发一个可安装的 Android APK，用于保存销售与客户沟通的录音，并自动生成会议记录和待办事项。

核心流程：

```text
测试人员在设置入口手动填写阿里云 API Key
    ↓
开始录音 → 停止录音 → 保存音频到手机
    ↓
App 直接向 Qwen Omni 提交完整音频
    ↓
生成会议摘要、关键事项、待办列表
    ↓
保存结果，在历史记录中查看和回放
```

目标录音场景为现场麦克风录音，不包含电话或微信通话的自动录音。

## 2. 已确定的技术栈

| 部分 | 选择 |
| --- | --- |
| 目标平台 | Android APK |
| App 框架 | uni-app |
| 页面与逻辑 | Vue 3 + JavaScript |
| 开发工具 | HBuilderX，优先使用 App 开发版 |
| 打包方式 | 优先使用 HBuilderX 云打包，交付可独立安装的 APK |
| AI 模型 | `qwen3.5-omni-plus` |
| 模型调用 | App 通过 HTTPS 直接调用阿里云，接收流式文本结果 |
| 数据保存 | 手机本地音频文件 + 简单本地记录存储 |
| 自建后端 | 不搭建 |
| 独立数据库、OSS | 第一版不搭建 |

### 模型路线决策

最终采用 Omni 直接理解音频、生成会议记录和待办。

此前讨论的“独立 ASR 转写 + Qwen3.7-Plus 总结”以及“手机端音频切分、多段转写、合并文字”均不作为第一版方案。选择 Omni 的主要原因是减少开发环节。

完整逐字转写不作为第一版必交付项，不增加独立 ASR 调用。

## 3. 页面与功能

### 3.1 首页

- 开始录音、停止录音。
- 显示录音状态和时长。
- 可填写客户名称作为简单标签，不建设客户管理系统。
- 展示历史记录及其处理状态。
- 点击历史记录进入详情。

### 3.2 记录详情

- 播放原始音频。
- 查看会议摘要、关键事项、待办列表。
- 显示模型处理状态及失败原因。
- 生成失败后允许重试，并保留原始音频。

### 3.3 API Key 设置入口

- 测试人员手动填写阿里云百炼 API Key。
- 允许修改或清除，输入时遮蔽显示。
- 不将真实密钥写入源码、配置样例或 APK。
- 日志不得输出密钥。
- 第一版可只在当前会话中保存，重新启动 App 后重新填写；已保存的音频和会议结果不依赖 Key 才能查看。
- 使用北京地域接口及对应地域的 Key；接入时核对模型权限与实际可用域名。若使用业务空间专属域名，需配置对应 Workspace ID，不能假设可从 API Key 推导。

## 4. 录音与音频提交

### 4.1 开发目标

支持约 30 分钟的前台录音和整段分析，第一版不做自动音频切分。

录音过程直接编码并写入音频文件，不需要录完后再做一次“录音转音频”。优先采用压缩音频格式，以兼顾音质和提交大小。

### 4.2 模型限制

按 2026-09-10 查阅的阿里官方文档：

| 提交方式 | 音频时长上限 | 大小限制 |
| --- | --- | --- |
| Base64 直接提交 | 3 小时 | 编码后的 Base64 字符串必须小于 10MB |
| 公网音频 URL | 3 小时 | 文件不超过 2GB |

当前 Demo 采用 Base64 直接提交，不依赖自行搭建的文件存储。

**模型支持 3 小时，不等于这个 Demo 能直接上传任意 3 小时录音。当前主要边界是 Base64 编码后的大小。**

30 分钟录音的理论大小估算如下，忽略少量封装开销：

| 码率 | 原文件大小 | Base64 后大小 |
| --- | --- | --- |
| 24 kbps | 约 5.4MB | 约 7.2MB |
| 32 kbps | 约 7.2MB | 约 9.6MB |
| 64 kbps | 约 14.4MB | 约 19.2MB，超限 |

上述码率只是验证候选，不能视为已经在 uni-app 安卓端验证可用。开发时需核实录音接口实际支持的格式、码率、时长及音质，检查实际文件大小并留出余量。

### 4.3 文件处理规则

- 录音结束后将临时音频持久保存，历史记录引用持久路径。
- 提交模型前检查文件是否存在、是否为空、Base64 编码后是否超限。
- 超限时明确提示，保留音频，不静默截断，不自动切分。
- 关闭并重新打开 App 后，仍能播放已保存的音频并查看结果。
- 卸载或清除应用数据后的恢复不在范围内。

### 4.4 运行范围

- 演示以 App 保持前台为范围。
- 不承诺长时间锁屏录音、后台保活或进程被杀后的自动恢复。
- 录音和历史查看可离线使用，AI 处理需要联网。

## 5. 模型输出要求

仅输出文字，不生成语音。输出包含：

1. **会议摘要**：概括沟通主题和主要结论。
2. **关键事项**：根据实际内容提取客户需求、价格、数量、交期、问题与已确认事项。
3. **待办列表**：任务内容、负责人、截止时间。

输出规则：

- 没有明确待办时显示“未发现明确待办”，允许待办列表为空。
- 未明确负责人或截止时间时留空或标记“未明确”，不猜测。
- 区分询问、提议和最终确认，不把讨论中的可能性写成承诺。
- 存在变更时体现最终明确确认的结论；存在矛盾且无法判定时标记待确认。
- 听不清或有歧义的内容标记待确认。
- 采用固定结构的提示词，并对返回结果进行必要校验。
- 不假设模型始终返回合法 JSON；解析失败或响应不完整时给出可理解的状态，并允许重试。
- 不把尚未完成的流式结果标记为完整成功。

## 6. 本地保存内容

每条记录仅需保存必要信息：

- 记录 ID、创建时间、客户标签。
- 音频持久路径、实际时长、文件大小。
- 处理状态和失败信息。
- 已完成的会议摘要、关键事项、待办列表。

不增加独立数据库服务，也不为 Demo 建设复杂的数据版本系统。

## 7. 基础异常处理

覆盖以下情况即可：

- 麦克风权限拒绝、录音失败。
- 音频为空、文件不存在、文件超限。
- API Key 缺失或无效、模型无权限。
- 网络中断、请求超时、接口失败或限流。
- 流式响应中断、输出不完整、结果解析失败。
- 请求期间避免重复点击产生重复调用。
- 模型调用失败保留音频，支持重新生成。

## 8. 明确不做的功能

- 登录、用户体系和权限管理。
- 客户管理系统、商机管理、CRM 同步。
- 实时字幕、说话人身份识别、逐句时间戳回查。
- 独立 ASR、音频自动切分、多段转写合并。
- 待办指派、提醒和完成流转。
- 云存储、服务端任务队列、复杂重试调度。
- 后台长时间录音、电话或微信通话自动录音。
- 完整逐字稿作为必须验收的成果。

## 9. 建议开发顺序

先完成技术验证，再完善两个主要页面：

1. 创建 uni-app + Vue 3 项目，连接安卓真机。
2. 验证录音、持久保存、回放，以及约 30 分钟录音的实际格式、大小和质量。
3. 验证手动填写 API Key、音频 Base64 直接提交和 Omni 流式结果接收。
4. 完成会议记录展示、本地历史与基本失败重试。
5. 生成可独立安装的 APK，在安装包中完成验收。

如果 uni-app 在长录音、Base64 读取或流式请求上存在限制，先核实并说明最小解决方案，不默认增加后端、音频切分或复杂架构。

## 10. 验收标准

- 可在 Android 真机安装和启动 APK。
- 测试人员可以在设置入口手动填写 API Key。
- 可以录制一段约 30 分钟的客户交流，保存并回放完整音频。
- 在音频满足大小限制的前提下，整段提交并生成可读的纪要与待办。
- 金额、数量、交期和行动承诺可对照录音核实，不将猜测当成事实。
- 重新启动 App 后，仍可查看历史音频和已保存结果。
- 超限、权限拒绝、网络失败等情况有明确提示，原音频不因模型失败而丢失。
- 验收基于实际安装的 APK 和真实模型调用，不能仅凭浏览器页面预览判定完成。

## 11. 成本参考

按北京地域公开价格、不计免费额度与失败重试，30 分钟音频、500 Token 提示词、1,500 Token 文字纪要，估计 Omni Plus 单次约 **0.73 元**。

计算依据：

- `qwen3.5-omni-plus` 音频输入按每秒 7 Token 折算。
- 音频输入 53 元/百万 Token，文本输入 7 元/百万 Token，文本输出 40 元/百万 Token。
- 30 分钟音频为 12,600 音频 Token。
- 仅生成文字，不使用音频输出价格。

此前估计“ASR + Qwen3.7-Plus”约 0.43 元/次。当前选择 Omni 是为了降低 Demo 开发复杂度，不是因为其单次模型费用最低。以上仅为估算，实际费用以调用用量及当期官方价格为准。
